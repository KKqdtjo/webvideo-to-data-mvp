# 具身数据相关文献整理与思考

整理时间：2026-08-15

这份笔记主要围绕四个近期工作展开：Track2Act、HOWTransfer、VideoManip、NVIDIA V2D/CHORD。它们共同关心一个问题：如何把人类视频中的操作知识转化为机器人可用的数据、轨迹或策略。相比直接讨论“视频能否变成机器人 action”，更值得关注的是这些工作各自选择了什么中间表示，以及这些表示如何缓解 human-to-robot 的 embodiment gap。

一个比较清楚的演进线是：

```text
2D point motion
    -> hand/contact trajectory
    -> 3D hand-object interaction
    -> object-centric contact physics
```

也就是说，这条研究线并不是简单地把 human hand trajectory 越恢复越精细，而是在不断寻找更适合跨 embodiment 迁移的表示。从视觉点运动，到接触时序和抓取意图，再到完整 3D 手物交互，最后到物体受到的力和力矩，表示越来越接近任务本身的物理结构。

## 1. Track2Act：从互联网视频中学习物体点运动

论文：Track2Act: Predicting Point Tracks from Internet Videos enables Generalizable Robot Manipulation
会议：ECCV 2024
来源：https://arxiv.org/abs/2405.01527
项目页：https://homangab.github.io/track2act/

Track2Act 的切入点很有代表性：它没有试图恢复人的手，也没有直接预测机器人 action，而是把人类视频中的操作知识压缩成一种更轻量的中间表示：2D point tracks。

它的直觉是，很多操作任务中真正重要的不是人的手如何运动，而是目标物体应该如何运动。例如“把杯子推到右边”这个任务，人的手只是实现方式，杯子表面点的运动轨迹才更接近任务结果。Track2Act 因此从互联网视频和机器人视频中学习一个 point-track predictor。给定当前图像、目标图像和物体上的若干点，模型预测这些点未来在图像平面中的轨迹。

部署到机器人时，系统利用 RGB-D 相机得到初始点的 3D 坐标，再根据预测的 2D tracks 反推出物体的 SE(3) 刚体运动。随后把这个物体运动转换成机器人 end-effector 的 open-loop trajectory。由于几何推断和实际执行之间会有误差，论文又用少量机器人数据训练 residual policy，对 open-loop plan 做闭环修正。

这篇工作的价值在于，它展示了互联网视频可以作为 manipulation prior 的来源，而且不必一开始就恢复完整 3D hand-object interaction。2D point tracks 是一种相对便宜、通用、跨 embodiment 的表示。

但它的限制也很明显。Point tracks 更擅长描述“物体看起来怎么动”，对于抓取稳定性、接触方式、力控、遮挡和复杂多阶段任务表达不足。因此 Track2Act 仍然需要 residual policy，并且更适合短时、刚体、单物体或相对清晰的操作。

对我们选题的启发：如果要从互联网视频或低质量视频中提取具身数据，不一定要一步到位恢复 3D 轨迹。可以先把 point tracks 作为低成本 operator，用于判断视频中是否存在可用的物体运动信号。

## 2. HOWTransfer：接触时刻和抓取意图比手轨迹更关键

论文：Hand-centric Human-to-Robot Trajectory Transfer from Video Demonstrations via Open-World Contact Localization
简称：HOWTransfer
来源：https://arxiv.org/abs/2606.10743

HOWTransfer 更直接面对 human video 到 robot trajectory 的转换。它的基本判断是：人的 wrist trajectory 有用，但不能直接复制给机器人。原因是人手和二指夹爪的结构差异很大。人的五指可以包裹、捏、支撑、调整，二指夹爪则只能实现有限的抓取模式。如果只把人的手腕轨迹 retarget 到机器人末端，机器人很可能在错误的时刻闭合夹爪，或者用不合理的姿态接触物体。

因此 HOWTransfer 把问题拆成几个环节：先从 stereo human video 中恢复 3D hand/wrist trajectory，再通过 open-world contact localization 找到有意义的 contact interval。Contact onset 被当作一个关键锚点，因为它通常对应人真正开始抓取或操纵物体的时刻。系统随后根据这个时刻的人类抓取意图生成适合 parallel-jaw gripper 的 grasp hypotheses，再沿着恢复出来的 wrist trajectory 传播，得到机器人可执行的 end-effector trajectory。

这篇论文最值得注意的是 contact localization。它不是简单地通过手指距离判断是否接触，而是综合 hand closure、hand visibility、hand-object proximity、物体 mask、手和物体是否共同运动等证据，找出真正和任务有关的接触片段。

它的核心贡献可以概括为：把 human-to-robot trajectory transfer 从“复制手的运动”改成“找到接触时序，识别抓取意图，再生成机器人自己的抓取轨迹”。

这让它比 Track2Act 更关注操作动作中的结构信息，尤其是接触阶段。它也比完整 3D reconstruction 更轻量，因为它不强依赖完整的 object mesh 或 6D object tracking。

局限是它主要面向 parallel-jaw gripper。对于灵巧手、in-hand manipulation、复杂双手协调等任务，单纯的 wrist trajectory 和二指夹爪 grasp taxonomy 不够。此外，它生成的仍然主要是 trajectory，而不是经过完整物理验证的闭环策略。

对我们选题的启发：如果做 embodied data pipeline，contact interval 应该是非常重要的数据字段。很多视频是否有价值，取决于能否可靠定位“接触开始、保持、释放”这些阶段，而不只是能否生成 caption。

## 3. VideoManip：把 RGB 视频恢复成 3D 手物交互，再训练灵巧手策略

论文：Dexterous Manipulation Policies from RGB Human Videos via 3D Hand-Object Trajectory Reconstruction
简称：VideoManip
来源：https://arxiv.org/abs/2602.09013

VideoManip 的目标比 HOWTransfer 更进一步：它希望直接从 monocular RGB human video 中学习 dexterous manipulation policy。这里的机器人不是简单二指夹爪，而是多指灵巧手，因此 7D end-effector action 已经不够，需要恢复和学习更高维的手部关节配置以及手物交互结构。

它的 pipeline 可以理解为四步。

第一步，从 RGB 视频中估计 metric depth 和 camera intrinsics。第二步，分别恢复 human hand pose、object mesh 和 object 6D pose。第三步，把 human hand-object trajectory retarget 到 robot hand 上，并通过 contact optimization 修正手和物体之间不合理的穿模、悬空或接触错误。第四步，通过 demonstration synthesis 扩增轨迹，再训练 3D diffusion policy。

VideoManip 的关键在于显式 3D 表示。它不满足于图像层面的 motion，也不只是找 wrist trajectory，而是试图恢复完整 hand-object interaction。对于灵巧手任务，这一点非常重要，因为手指和物体之间的相对位置、接触点、物体姿态变化，都会直接影响执行结果。

它还有一个值得借鉴的思路：一条视频本身不够训练 robust policy，所以需要把重建得到的轨迹做空间变换和合成。也就是说，视频提供的是一个核心交互模板，之后通过一致的 SE(3) transformation 生成更多训练样本，使策略适应不同物体初始位置。

局限也很明确。VideoManip 需要串联多个 3D vision module，包括 depth、hand reconstruction、object mesh reconstruction、6D pose estimation、retargeting 和 contact optimization。每一步都有误差，误差会逐级传递。论文也承认当前更适合大致 egocentric、相机相对稳定、手物关系清楚的视频，而不是任意互联网视频。

对我们选题的启发：VideoManip 提醒我们，简单说“从网上爬视频做 video-to-data”是不够的。真正能转成机器人数据的视频，需要满足一些可重建条件，比如手部清晰、物体可分割、相机运动不过分剧烈、接触阶段没有严重遮挡。因此，做“视频质量评估”和“可重建性评分”可能比直接做大规模转换更现实。

## 4. NVIDIA V2D：把 video-to-data 工程化成完整数据流水线

项目：Video to Data, NVIDIA Isaac
来源：https://github.com/nvidia-isaac/video_to_data

NVIDIA V2D 更像一个系统级工程，而不是单一算法。它的目标是把 human demonstration video 转换为 simulation-ready assets 和 physics-grounded robot training data。

官方 pipeline 分成三大阶段：

```text
Video Ingestion
    -> Reconstruction
    -> Robotic Grounding
```

Video Ingestion 负责把长视频切成 temporally-bounded action clips，抽取 entity-relation scene graph，并保存 frame embeddings，使后续可以用自然语言检索相关片段。

Reconstruction 阶段负责把选中的视频片段转成深度、mask、mesh、6D object pose 和 human body parameters 等 3D 资产。

Robotic Grounding 阶段则把 human motion retarget 到目标机器人 embodiment，并在 Isaac Lab 中进行 RL 训练，最终得到可部署的 policy。

这套系统最值得注意的不是某一个模型，而是它的工程分层思想。它把 video-to-data 拆成可组合、可缓存、可检查的阶段。每个阶段都把中间结果写到磁盘，这样可以单独调试、替换模块、重跑下游流程。这和 DataFlow 的 operator/pipeline 思想非常接近。

对我们选题的启发：如果我们要做一个 DataFlow-Embodied 类型项目，不一定要复刻 V2D 的 reconstruction 和 grounding。更现实的切入点是做 V2D 前面或旁边的一层：面向 web/ego video 的筛选、评分、切片、标注、质量报告和格式转换。这些模块可以轻量，但必须可组合、可复现、有清楚的数据 schema。

## 5. CHORD：从模仿 trajectory 转向模仿物体受到的物理作用

论文：Learning Dexterous Manipulation Using Contact Wrench Guidance From Human Demonstration
简称：CHORD
来源：https://arxiv.org/abs/2607.00033

CHORD 是这几篇里思想最“物理化”的工作。它关心的问题是：对于 contact-rich dexterous manipulation，机器人是否应该模仿人的手轨迹？它的回答是否定的，至少不是只模仿轨迹。

人的手和机器人的手结构不同，接触点也可能不同。如果强行要求机器人在和人相同的位置接触物体，反而会限制机器人发挥自身 embodiment 的能力。真正重要的是，人的接触对物体产生了什么作用，例如推动、旋转、支撑、拉开、压住。这些作用可以用 contact wrench 描述，即物体受到的 force 和 torque。

CHORD 的核心是 object-centric contact wrench space。它把 human motion 和 robot motion 都映射到物体中心的接触力/力矩空间中，用它们能够诱导的瞬时物体运动来衡量相似性。这样，机器人不需要复制人的手部动作，只要找到一种自己的接触方式，使物体产生相似的运动效果。

这一步很重要，因为它把跨 embodiment 的中间表示从 kinematic trajectory 推进到了 interaction physics。前面几篇主要在问“如何从视频得到更好的 trajectory”，而 CHORD 开始问“trajectory 是否是最本质的监督信号”。对于双手、灵巧手、接触丰富的长时任务，物体中心的物理效果可能比手的位置更稳定。

CHORD 也展示了大规模 simulation benchmark 和 RL 结合的潜力。它构建了数千个双手灵巧操作任务，并在大量评测任务上报告了较高成功率。但它的代价也明显：依赖仿真、物理建模、任务重建和强化学习，整体工程门槛远高于 Track2Act 或 HOWTransfer。

对我们选题的启发：如果短期不做完整 physics RL，也可以先借鉴 CHORD 的思想，把“contact physics readiness”作为数据质量维度。例如，一个视频片段是否能估计出物体运动？是否有明确接触阶段？是否能推断出接触导致的运动变化？这些都可以作为 embodied data scoring 的指标。

## 6. 四篇工作的对比

| 工作 | 中间表示 | 数据来源 | 输出 | 优点 | 主要限制 |
| --- | --- | --- | --- | --- | --- |
| Track2Act | 2D point tracks | web videos + robot videos | object motion, EE trajectory, residual policy | 轻量，适合大规模视频，跨 embodiment 简单 | 接触和抓取表达弱 |
| HOWTransfer | 3D wrist, contact interval, grasp intent | stereo human videos | parallel-jaw EE trajectories | 抓住 contact onset，适合二指夹爪迁移 | 不适合复杂灵巧手 |
| VideoManip | 3D hand-object trajectory | monocular RGB human videos | dexterous hand demonstrations and policy | 显式 3D 交互，适合灵巧操作 | 视觉模块多，误差累积 |
| V2D | ingestion, reconstruction, grounding pipeline | human demonstration videos | simulation-ready assets, robot training data | 系统完整，工程分层清楚 | 工程量和硬件门槛高 |
| CHORD | object-centric contact wrench | human demos + simulation tasks | RL policy | 从物理效果层面处理 embodiment gap | 依赖仿真和物理重建 |

## 7. 对我们项目方向的思考

这几篇论文共同说明一件事：human video 不是天然的 robot data。它必须经过中间表示提取、质量筛选、物理或几何 grounding，才可能成为有用的训练数据。

如果我们直接做“从互联网爬大量视频，然后转成机器人数据”，很容易被质疑。互联网视频数量确实大，但其中很多视频没有清晰手部、没有完整接触过程、视角不稳定、遮挡严重、缺少深度和相机参数。数据量本身不能解决这些结构性缺陷。

更稳妥的方向是把问题改成：

```text
从低质量、非结构化、互联网规模视频中，自动发现哪些片段包含可迁移的具身操作信息。
```

这样项目的核心不是“所有视频都能转成 action”，而是“哪些视频值得转，能提取出什么层级的表示，提取结果有多可信”。

一个可行的 DataFlow-Embodied 思路是，把这些论文中的中间表示做成不同层级的 data operators：

```text
Video
    -> manipulation clip
    -> point tracks
    -> hand/object/contact
    -> 3D reconstruction readiness
    -> robot-transfer readiness score
    -> LeRobot/RLDS-like metadata
```

其中比较适合第一版实现的模块包括：

1. Video clip segmentation：从长视频中找出可能包含操作动作的片段。
2. Point-track extraction：提取物体或手附近的可追踪点，参考 Track2Act 的思想。
3. Contact interval estimation：检测接触开始、保持和释放，参考 HOWTransfer。
4. HOI quality scoring：判断手、物体、接触、遮挡、相机运动是否满足后续处理要求。
5. Object counterfactual augmentation：做苹果换梨一类增强，但需要保持接触和语义一致。
6. Format exporter：输出 LeRobot 或 RLDS 风格 metadata，方便后续接入训练流程。

这样做的好处是工程量可控，也和 DataFlow 的 pipeline/operator 定位一致。它不需要一开始就做完整机器人训练，也不需要复刻 NVIDIA V2D 的 3D reconstruction 和 Isaac Lab RL。它可以先解决一个更前置但很关键的问题：具身视频数据的结构化、筛选和可迁移性评估。

## 8. 我认为最值得提炼的核心观点

第一，human video 到 robot data 的关键不是直接预测 action，而是寻找合适的 intermediate representation。

第二，表示越接近物体和接触本身，越可能跨 embodiment。Track2Act 用 object point motion，HOWTransfer 用 contact onset 和 grasp intent，VideoManip 用 3D hand-object trajectory，CHORD 用 object-centric contact wrench。

第三，互联网视频的最大价值不是“全都能用”，而是里面有大量稀疏的高价值 manipulation moments。需要先筛选，再转换。

第四，对于我们这样的开源项目，最现实的贡献可能不是完整 video-to-policy，而是 embodied data governance：给视频切片、打分、标注、增强、导出，并告诉用户这些数据适合进入哪一级后续处理。

第五，如果后续要做技术报告，可以把研究问题定义成：如何评估和组织 in-the-wild videos 中的具身操作信息，使其能够被不同下游 robot learning pipeline 使用。
